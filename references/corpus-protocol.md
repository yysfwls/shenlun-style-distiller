# 语料协议

## 最小分析单位

每个案例尽量包含：

```text
案例编号/
├── 题目.md
├── 给定材料.md
├── 范文.md
├── 讲解或批注.md      # 可选
└── metadata.yaml
```

只有范文时可以分析 L1 语言和部分 L2 结构，但 L3 审题立意、L4 材料转化和 L5 认知框架必须降级置信度，并在总报告首页声明限制。不得从缺失的题目或材料反推原始要求。

## 建议规模与采样

- 每位作者约 20 篇完整范文可形成第一版基础画像，不是保证可靠性的硬阈值。
- 尽量覆盖不同年份、地区、主题和题型，避免同一课程的一稿多发或轻微改稿重复计数。
- 优先收集两位作者对同一道题的范文；同题比较最能隔离题目变量。
- 语料足够时，每位作者保留约 20% 不参与提炼，用于留出验证。
- 记录是否可能为团队稿、编辑改稿、学员稿或转载；来源不明的文本不能直接代表作者。

## 客观元数据

建议使用以下字段；未知值写 `unknown`，不要猜测：

```yaml
case_id: BL-001
author: 白鹭
title: ""
source_file: ""
source_url: ""
published_at: ""
exam_name: ""
exam_year: ""
exam_region: ""
prompt_text_available: true
source_material_available: true
commentary_available: false
word_limit: ""
essay_char_count: 0
authorship_status: confirmed  # confirmed / probable / unknown
paired_case_id: ""           # 对方作者同题案例
notes: ""
```

主题、题型、文章类型、hook、论证方式和段落功能不是客观元数据，应在统一 codebook 建立后写入 `_annotations/`。

## 原始文件纪律

- 保留原始文件，不覆盖、不“清洗后替换”。
- 转换格式时保存来源链接、抓取日期和转换说明。
- 识别重复、转载、残缺正文和一稿多发；重复文本只计一次。
- 自动抓取只有在用户明确要求且访问条件允许时进行；付费墙、登录内容或失败页面不绕过限制。
- 长篇原文只用于用户授权的分析和本地研究，不把大段原文复制进 Writing DNA。

## 缺失材料时的停止条件

以下情况不阻止建立基础语料清单，但必须暂停深层归因并向用户索取材料：

- 无法确认哪篇范文属于哪位作者；
- 范文正文严重残缺；
- 需要分析材料转化，但没有题目和给定材料；
- 需要做同题比较，但无法匹配两位作者的题目；
- 文件是图片且文字无法可靠识别。
