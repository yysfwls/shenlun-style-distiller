# 比较、应用与验证

## 双作者比较

先分别完成两位作者的独立蒸馏，再比较。证据等级从强到弱：同题同材料、同主题相近题型、不同题目的跨语料稳定特征。每项差异都标明证据等级，不用“更有文采”“更务实”等无法执行的标签代替分析。

同题比较时逐步对齐：题干解释 → 中心立意 → 分论点来源 → 材料选择 → 段落推进 → 价值收束。若题目不同，先控制题型、主题和字数，再解释剩余差异。

## 使用 DNA 写作

1. 按 `input-intake.md` 独立完成题目约束和材料事实清单。
2. 从 DNA 选择适配当前题型的高置信度规则，不加载所有模板。
3. 给出中心论点、分论点及其材料依据；无法从材料支持的观点要删去或降级。
4. 先生成结构和段落功能，再生成句子。
5. 限制语言层规则的密度，防止口头禅和排比机械复现。
6. 按对应作者的应用检查表审稿；题目与事实问题优先于风格问题修复。
7. 用户要求成稿且工作区可写时，按 `runtime-output-contract.md` 保存分析、材料映射、纯净成稿和验证报告。

如用户要求融合两位作者，必须先说明各自承担的层级，例如“采用 A 的立意方法和 B 的段落论证”，不能把词句混合当成方法融合。

## 验证与更新

留出案例不参与规则发现。验证时检查高置信度规则能否解释留出文本、哪些规则只适用于训练语料、是否出现反例，以及差异是否实际由题目或材料造成。

新题验证要分开检查题意符合度、材料忠实度、论证质量、原创性和规则执行度。能够区分两位作者不代表质量合格；如果风格执行导致偏题或事实错误，验证失败。

新增语料时追加版本，不静默覆盖旧结论。记录新增案例、规则升降级、被反例推翻的结论和版本日期。孤立的新例外不立即写成普遍规则。

成稿字数和明显占位符使用 `scripts/validate_essay.py` 机械复核；脚本通过不代表题意、材料事实或论证质量已经合格。
